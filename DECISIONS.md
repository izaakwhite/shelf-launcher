## Choices
| CPU | 4 cores, slow; ~18 ms GPU time for a full-screen redraw of a busy frame |
| TV inputs | `com.tcl.tvinput` passthrough HDMI 1–3 + "Cable", hardware tuner "Antenna TV" |

### Toolchain
- JDK: the `temurin@17` cask needs `sudo` (no terminal for the password), so I used the `openjdk@17` **formula**
  (no sudo). `env.sh` sets `JAVA_HOME`/`ANDROID_HOME`.
- Versions looked up at build time (Google Maven / Maven Central): AGP 9.5.1 (built-in Kotlin), Kotlin 2.4.21
  (Compose compiler plugin), Gradle 9.9.0, Compose BOM 2026.09.00, tv-material 1.1.0, activity-compose 1.13.0,
  datastore 1.3.0, palette 1.1.0. compileSdk 37.
- `targetSdk 36` instead of 28: release lint refuses old targets, and newer-target behaviour changes only apply on
  newer OS versions, so nothing changes on this API 28 TV. `minSdk 28`.
- `androidx.tv:tv-foundation` isn't used: its lazy lists are deprecated in favour of Compose foundation, and
  focus here is handled explicitly (see below). `tv-material` is used for dialogs, buttons and list items.

### Home behaviour
- `cmd package set-home-activity` **works** on this API 28 build. Shelf is the default home.
- Installing a second HOME app makes Android forget the default home, so `deploy.sh` records the default home before
  installing and restores it if it changes.
- Home pressed while already on Shelf → back to the first item (window-focus + not-BROUGHT_TO_FRONT check, as Launcher3 does).
  Home from another app → focus restored to the last item.

### Layout / focus
- Focus is never left to geometric search where it misbehaved: the grid scrolls deterministically to the focused row;
  the carousel keeps the focused icon centred; pills have explicit left/right/up wiring (geometric search used to jump
  from a pill into the carousel); Wave is a single focus target with its own selection state, so focus can't get lost.
- Labels: banner tiles show a label under the focused tile; generated tiles (icon on a sampled colour) already
  contain their name, so they don't repeat it underneath.
- First run: favourites seeded from installed streaming apps; TCL's internal utility activities (Initial Setup, OTA,
  BT RCU test, User Agreement, TvKitServer) start hidden. All of this is reversible.
- Wallpaper lives in the app's *external* files dir because `adb push` can't write the internal one on a release build.

### Redesign during the session (user requests)
- "Frosted glass" (user asked for a glass look): panels draw the pre-blurred backdrop at their own screen position (frosted with zero real-time
  blur), plus tint, specular sheen and a gradient rim. Clock centred in a glass pill.
- Frutiger-Aero backdrop drawn in code (`AeroArt.kt`): gradient, blooms, light rays, aurora ribbons, glossy bubbles.
  Three palettes: Aqua, Dusk, Night.
- Carousel of square icons: adaptive icons drawn full-bleed from the xxxhdpi resource; legacy icons on a colour sampled
  from the icon; Aero gloss + rim and rounded corners baked into the bitmap.
- A console-dashboard look → **Wave** style: a category bar + vertical list *interaction* only. Original line icons, an original
  procedurally drawn ribbon, an original slow hue cycle, a date/time format of MM/DD/YYYY, no per-month tint. **No third-party assets or names.**
- Requested console-style sounds → original synthesized sounds (`res/raw/sfx_*.wav`, generated by a script) in that spirit: tick, slide,
  two-note OK chime, falling Back note. Recorded console audio/music is copyrighted and is not included; users can supply their own music file.
- The original grid layout is kept as a third style.

### Inputs
- `TvContract.buildChannelUriForPassthroughInput(id)` with `ACTION_VIEW` **works**: it resolves to `com.tcl.tv/.TVActivity`
  and switches input (verified on HDMI 1). TCL-specific fallbacks remain in code but weren't needed.
- After a reboot TCL's input service registers after the launcher starts, so the list is reloaded on every resume and
  retried a few times while empty.

### Performance (measured on the TV)
- AOT: `deploy.sh` runs `cmd package compile -m speed` (the JIT warm-up otherwise causes 1–3 s frames).
- Things that made the difference on this GPU: caching every glass panel and the whole static backdrop as one offscreen
  texture; dropping the window background (it was a second full-screen fill); baking rounded corners into icon bitmaps
  (no per-tile GPU clip); `ModulateAlpha` instead of offscreen layers for faded items; caching tilted Wave rows as
  textures (perspective text is very slow); debouncing the hero/info panel; scoping recomposition with `snapshotFlow`.
- `input keyevent` starts a Java process per key (~1 s of CPU on this SoC), which itself causes jank. The numbers below
  give both that method and native `sendevent` injection on the `sim-kb` device, which matches a real remote.

| Measurement | Result | Budget |
|---|---|---|
| Aero, 50 D-pad presses (sendevent) | **4.42 % janky**, p50 11 ms, p90 14 ms | < 5 % |
| Aero, 50 D-pad presses (`input keyevent`) | 6.08 % janky | |
| Wave, idle (ribbon animating) | ~12 % janky, p50 11 ms | |
| Wave, 50 D-pad presses (sendevent) | **74.5 % janky**, p50 18 ms | over budget |
| Cold start → interactive (process start incl.) | **1.19–1.33 s** (first frame 0.48 s) | < 1.5 s |
| Memory (PSS) | **42 MB** | < 150 MB |

- Wave misses the 60 fps budget while navigating, because its continuous background animation means every frame
  repaints a large area. Settings → Reduce motion stops the ribbon and the hue cycle. Aero (default) is within budget.
- `screenrecord` starves this SoC (drops input, collapses frame rate), so it's no good for judging smoothness.

### Persistence
- Order, favourites, hidden apps and style survived `am force-stop` and a TV reboot (verified 2026-11-09).

### Known issues
- The first D-pad press right after returning home from another app is occasionally swallowed.
- Wave navigation jank (above).
